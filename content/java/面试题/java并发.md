## 1 java并发

### 1.1 基础概念与线程管理

#### 1.1.1 进程与线程的区别是什么？


进程与线程的区别主要体现在以下几个方面：

1. 基本单位
   (a) 进程是资源分配的基本单位。
   (b) 线程是 CPU 调度的基本单位。

2. 内存空间与资源共享
   (a) 内存空间：进程之间相互独立，拥有独立的内存地址空间；而线程共享所属进程的内存空间。
   (b) 资源共享：线程可以共享进程的堆、方法区等资源。
   (c) 私有资源：每个线程拥有自己独立的程序计数器、虚拟机栈和本地方法栈。

3. 创建与开销成本
   进程的创建与销毁涉及资源的分配与回收，切换成本和开销都很高；相比之下，线程的创建和切换成本更低，也更轻量。

 4. 通信方式
在通信方式上，进程与线程存在显著差异：

5. 进程通信
   进程之间需要更高程度的隔离，必须经过特定的 IPC（进程间通信）机制。通信方式相对复杂，常见的包括：
   (a) 管道
   (b) 消息队列
   (c) 共享内存等

6. 线程通信
   由于线程共享所属进程的资源，通信实现相对简单。线程只需读取全局变量（即通过共享资源）即可实现数据交换。



#### 1.1.2 创建线程有哪几种方式？推荐哪种？

创建线程归根结底都是调用 Thread 类的 run 方法。在形式上，主要有以下几种方式：

1. 继承 Thread 类
   通过继承 Thread 类并重写其 run 方法来实现。

2. 实现 Runnable 接口
   实现 Runnable 接口并重写 run 方法。

3. 实现 Callable 接口
   实现 Callable 接口并结合 FutureTask 来创建线程。

4. 使用线程池
   直接创建一个线程池，由线程池自动帮你创建并管理线程。线程池会自动处理线程的创建、分配与销毁。

实际上，无论是哪种创建线程的方式，到最终都需要去调用 Thread.start 方法。也就是说，虽然形式有很多，但实际上 Thread.start 才是唯一的入口。

比如说，对于继承 Thread 类的方式，它的本质在于：
1. 其内部已经实现了 Runnable 接口
2. 最终的执行依然是依靠其内部实现的 run 方法






#### 1.1.3 run() 和 start() 有什么区别？

1. run() 是一个普通的方法：
   调用 run() 只是在当前线程中执行普通的方法逻辑，并不会开启新的线程。

2. start() 才是真正启用线程的方法：
   调用 start() 会通知 JVM 创建一个新的线程路径（线程实例），并由这个新线程去异步执行 run() 方法中的逻辑。

3. 调用限制：
   每个线程对象的 start() 方法只能被调用一次。如果重复调用，系统会抛出异常。




#### 1.1.4 线程的生命周期（状态）有哪些？状态之间如何转换？
线程的状态共有 6 种：

1. 新建状态 (NEW)
   线程对象已经创建，但是还没有调用 start() 方法。

2. 可运行状态 (RUNNABLE)
   调用了 start() 方法之后进入这个状态。这里的 RUNNABLE 实际上包含了操作系统层面的两种状态：就绪 (Ready) 和运行中 (Running)。也就是说，线程在 start() 之后不一定会马上运行，它只是可以被 CPU 调度了，具体执行时机取决于系统的调度。

3. 阻塞状态 (BLOCKED)
   通常表示线程正在等待获取监视器锁（lock）。

4. 无限期等待 (WAITING)
   线程需要等待其他线程进行显式唤醒。

5. 限时等待 (TIMED_WAITING)
   线程会等待一段时间，到期后会自动恢复，不需要手动唤醒。

6. 终止状态 (TERMINATED)
   线程执行完毕或者因异常结束。

状态转换过程：

1. 新建到就绪 (NEW → RUNNABLE)
   线程从新建状态进入启动阶段。

2. 阻塞状态 (BLOCKED)
   运行中的线程如果抢不到锁，会从 RUNNABLE 进入阻塞状态。

3. 等待状态 (WAITING)
   需要别人进行唤醒时，线程会从 RUNNABLE 转换到 WAITING 状态。

4. 限时等待 (TIMED_WAITING)
   如果是休眠或者限时等待的情况，线程会从 RUNNABLE 转换到 TIMED_WAITING。

执行结束的话，则会从 RUNNABLE 状态转为终止。



#### 1.1.5 .sleep() 和 wait() 的区别？


Sleep 和 Wait 的区别主要体现在以下几个方面：

1. 方法归属不同
   (a) Sleep 是 Thread 类的一个静态方法。
   (b) Wait 是 Object 类的一个方法。

2. 锁的释放机制（最核心区别）
   (a) Sleep 不会释放当前线程持有的锁。即便线程进入了休眠状态，它依然占据着锁资源。
   (b) Wait 会释放当前线程持有的锁，让出资源以允许其他线程进入同步代码块。

3. 用途与偏重点
   (a) Sleep 更偏向于线程调度，用于让当前线程暂停执行，休眠指定的时间。
   (b) Wait 更偏向于线程间的通信，它通常需要配合其他线程的唤醒操作（如 notify 或 notifyAll）来使用。

4. 使用位置
   (a) Sleep 可以在任何地方使用。
   (b) Wait 只能在同步代码块（synchronized block）或者同步方法中调用，否则会抛出异常。


#### 1.1.6 yield() 的作用是什么？
yield() 的作用是一个提示调度器，就是告诉 CPU 它可以暂时让出当前线程，让同优先级的其他线程先去执行。

但是，它只是提醒而非强制，调度器也可以完全不理会这个请求。

## 2 银行家算法

安全性检查算法:

1. 判断当前空闲资源 是否满足所有进程,从中选择出满足的 a进程
2. 再看除a之外的进程是否满足. 从中再选择满足的
3. |如果都不满足, 就认为是不安全的



总结
1. **在当前空闲资源下，从所有未完成的进程中找出**至少一个能满足其剩余需求（Need ≤ Work）的进程（例如 a）。
    
2. **假定 a 完成并释放资源**，更新空闲资源（Work += Allocation[a]），然后从剩下的未完成进程中继续寻找下一个能满足的进程。
    
3. **如果在某一步，找不到任何一个满足条件的进程**，而此时还有未完成的进程，那么系统就处于**不安全状态**；反之，如果所有进程都能依次完成，则是安全状态。
