1 java 集合

1.1 java有哪些集合类

Java 中集合的接口主要分为两大类：一个是 Collection 接口，另一个是 Map 接口。

  1. Collection 接口
    在 Collection 接口下，又分为 List 接口、Set 接口和 Queue 接口：
    (a) List 接口下的集合类有：LinkedList、ArrayList 以及 Vector
    (b) Set 接口下的集合类有：HashSet、TreeSet 以及 LinkedHashSet
    (c) Queue 接口下的集合类有：ArrayDeque 以及 LinkedList

  2. Map 接口
    Map 接口下的集合类主要有：HashMap、TreeMap 以及 LinkedHashMap

1.2 hashmap 的原理

在 Java 开发中，HashMap 主要用来存储键值对数据。随着数据量的增多，哈希冲突（Hash Conflict）不可避免。从 Java 8 开始，底层数据结构进行了重大优化，以解决其性能瓶颈。

HashMap 的原理可以概括为：使用“数组 + 链表 + 红黑树”的结构，通过哈希算法定位，利用链地址法解决冲突，并在特定条件下将链表转化为红黑树以优化性能。

为了进一步阐述，我们将 HashMap 的原理归结为三个层次：

  1. 数据结构
    (a) 数组作为底层：用于快速定位索引，可以看作是传统哈希表中的“桶”。
    (b) 链地址法：将键值对存储在数组中，当多个 Key 哈希到同一个位置时，形成链表进行存储。
    (c) 红黑树转化：当链表长度超过阈值（默认为 8）且数组长度超过 64 时，链表转化为红黑树。这使查询的时间复杂度从 O(n) 降低到 O(log n)。

  2. 存取流程
    (a) Put 流程：
    - 根据 Key 进行 Hash 运算，确定其在数组中的下标位置。
    - 如果该位置为空，直接插入。
    - 如果该位置已有元素，则判断 Key 是否相同。若相同则直接覆盖旧值；若不同则挂在链表或红黑树的后面。
    - 最后检查是否需要扩容或树化。
    (b) Get 流程：
    - 将输入的 Key 通过 (n-1) & hash 确定在数组中的位置。
    - 访问该位置的元素，如果命中头节点则直接返回。
    - 如果没有命中，则遍历链表或红黑树找到对应的 Key 并返回结果。

  3. 关键机制
    (a) 哈希扰动：通过高位参与运算，减少哈希碰撞，平衡性能和复杂度。
    (b) 扩容机制：默认初始容量为 16，负载因子为 0.75。当元素数量大于“容量 × 负载因子”时，会扩容为原来的两倍，并重新进行哈希分布。
    (c) 线程安全特性：HashMap 在设计上主要通过上述机制平衡性能，但在多线程环境下需要注意其非线程安全的特性。

1.3 为什么 JDK 8 对红黑树进行了改动？

为了解决链表长度过长时导致的性能查询问题。在 JDK 1.7 时，使用链表来处理冲突，当链表过长时，查询的时间复杂度为 O(N)。攻击者可以通过刻意构造超长链表，从而导致查询卡死。

针对这一问题，JDK 8 引入了红黑树：

  1. 当链表长度大于 8，且数组长度大于 64 时，会将链表转化为红黑树。
  2. 这一改进让性能从 O(N) 优化为了 O(logN)。
  3. 当红黑树的节点降到 6 以下时，会重新转化为链表。

树化需要满足链表长度大于 8 且数组长度大于 64。如果链表长度大于 8，但数组长度没有大于 64，系统会选择进行扩容，而不是进行树化。

原因如下：

  1. 在小数组中发生哈希冲突是非常正常的。
  2. 直接通过扩容增加槽位数量，就可以有效解决冲突问题。
  3. 在这种情况下强行树化，反而会浪费性能。

1.4 ArrayList 与 LinkedList 的区别？

ArrayList 和 LinkedList 都是 List 接口下的数据结构，由于底层的实现方式不同，导致其在性能和应用场景上存在很大差异：

  1. 底层数据结构
    (a) ArrayList：基于动态数组实现。
    (b) LinkedList：基于链表实现。

  2. 存储空间
    (a) ArrayList：支持连续存储，内存利用率更高，相对更加节省空间。
    (b) LinkedList：数据不是连续存储的，每个元素都需要额外的指针来指向下一个节点，因此会占据更多的内存空间。

  3. 操作性能
    (a) 查找：ArrayList 更加适合查找操作，其时间复杂度为 O(1)；而 LinkedList 不擅长查找。
    (b) 新增与删除：ArrayList 在新增操作上的时间复杂度通常为 O(n)（尤其是在非末尾位置插入时）；LinkedList 则更擅长存储和修改操作。

  4. 应用场景
    (a) ArrayList：适用于查询多、修改少的场景。在绝大多数实际开发场景中，都会优先采用 ArrayList。
    (b) LinkedList：适用于修改多、查询少，特别是需要在列表中间频繁进行插入和删除操作的场景。

1.5 ConcurrentHashMap 如何保证线程安全？

ConcurrentHashMap 实现线程安全的主要方式在不同版本的 JDK 中有所区别：

  1. JDK 1.7：采用分段锁（Segment）机制
    (a) 核心结构：分段锁是一个 Segment 数组，它继承了 ReentrantLock。
    (b) 并发度：默认有 16 个 Segment 数组，每个 Segment 独立进行加锁。
    (c) 工作原理：当线程访问某个 Segment 时，只会锁定该 Segment，而其他 Segment 仍然可供其他线程访问。
    (d) 性能：这种设计最大允许 16 个线程进行并发写入。

  2. JDK 1.8：采用 CAS + synchronized 的机制
    (a) 核心结构：引入了 Node 数组，不再锁定整个数组。
    (b) 细粒度锁：它只锁定链表或红黑树的头节点。
    (c) 写入过程：访问时会先使用 CAS 操作尝试进行写入。如果写入成功，则无需加锁，性能极高。
    (d) 冲突处理：如果 CAS 写入失败（发现桶内已有元素，发生了 Hash 冲突），则会使用 synchronized 锁定当前桶或当前树的头节点。

Node 节点的 val 和 next 指针使用 volatile 修饰，保证可见性，确保一个线程修改后其他线程立即可见。

2 基础语法

2.1 == 和 equals 的区别

在 Java 中，== 和 equals 的区别主要体现在以下两个方面：

  1. == 运算符
    (a) 对于基础类型：比较的是它们的数值是否相同。
    (b) 对于引用类型：比较的是它们的内存地址是否相同，即判断两个变量是否指向同一个对象。

  2. equals 方法
    (a) 在默认情况下（即 Object 类中的实现），它与 == 是完全相同的。
    (b) 逻辑比较：在实际开发中，我们更希望通过 equals 来比较两个对象的内容是否相同。如果两个对象的内容一致，我们通常希望 equals 返回 true。
    (c) 方法重写：像 String、Date 等类都重写了 equals 方法，从而使得它们比较的是对象的内容而非内存地址。

2.2 String、StringBuffer、StringBuilder 的区别？

  1. String
    (a) 字符串是不可变的
    (b) 每次修改时都会创建新的对象，性能较低
    (c) 线程安全

  2. StringBuffer
    (a) 可变的字符串序列
    (b) 方法加了 synchronized，线程安全
    (c) 性能一般

  3. StringBuilder
    (a) 可变的字符串序列
    (b) 非线程安全
    (c) 性能最高

2.3 基本数据类型与包装类的区别？

在 Java 中，基本数据类型（Primitive Types）和包装类（Wrapper Classes）的主要区别可以从以下几个维度来看：

2.3.1 核心区别对比

特性基本数据类型 (e.g., int, double)包装类 (e.g., Integer, Double)
存储位置栈（Stack）内存中直接存储值堆（Heap）内存中存储对象
默认值有默认值（如 int 为 0, boolean 为 false）默认值为 null
性能效率高，占用内存少效率较低，作为对象需要额外的开销
泛型支持不支持（不能用于 List<int>）支持（必须用 List<Integer>）
传递方式值传递引用传递（虽然包装类是不可变的）

2.3.2 为什么需要包装类？

  • 集合框架支持：Java 的集合类（如 ArrayList, HashMap）只能存储对象，不能直接存储基本类型。
  • 泛型需求：泛型类型参数必须是引用类型。
  • 包含工具方法：包装类提供了许多实用的方法，例如 Integer.parseInt() 或 Double.compare()。
  • 表示空值：在数据库操作中，某些字段可能为 NULL，基本类型无法表示这种状态，而包装类可以用 null 表示。

2.3.3 自动装箱与拆箱 (Autoboxing & Unboxing)

为了方便两者转换，Java 5 引入了自动机制：

  • 自动装箱：基本类型自动转为包装类。Integer a = 10;
  • 自动拆箱：包装类自动转为基本类型。int b = a;

注意： 在循环中使用自动装箱会产生大量无用对象，从而影响程序性能。

2.3.4 缓存机制

Java 为了优化性能，对部分包装类在一定范围内进行了缓存。例如：

  • Integer 缓存了 -128 到 127 之间的数值。
  • 如果在这个范围内比较两个 Integer 对象（使用 ==），结果为 true；超过这个范围，结果为 false（因为它们是不同的对象）。

建议： 比较包装类的值时，始终使用 .equals() 而不是 ==。

2.4 序列化与反序列化

就是将 Java 中的对象转换成二进制字节流，然后可以通过硬盘或者网络传输给其他机器；反序列化则是将字节流还原成 Java 对象。

具体实现方法如下：

  1. 实现 Serializable 接口
    在实体类中实现 Serializable 接口以启用序列化功能。

  2. 处理敏感字段
    对于密码等敏感字段，可以加上 transient 关键字，在序列化时将其跳过。

  3. 定义 serialVersionUID
    建议手动添加 serialVersionUID 作为一个版本号，防止在结构化时因版本不一致导致反序列化出错。

3 面向对象

3.1 面向对象三大特性？

面向对象的三大特性分别是封装、继承和多态：

  1. 封装
    是指隐藏内部细节，通过 public 来暴露一些方法供外部使用。

  2. 继承
    是指子类继承父类的非 private 成员。

  3. 多态
    是指同一方法在不同的对象中有不同的表现。实现多态需要满足三个条件：
    (a) 继承
    (b) 重写
    (c) 父类引用指向子类对象

3.2 重写与重载的区别

  1. 重写（Overriding）
    是指子类重写父类的方法。方法名、参数列表、返回值必须保持一致。
  2. 重载（Overloading）
    是指在同一个类中，允许存在同名但参数列表（参数类型或数量）不同的方法

3.3 抽象类与接口的区别？

这两者从设计理念上来讲有很大不同：

  1. 抽象类 (Abstract Class)
    (a) 它是我们写了很多代码之后，发现有很多重复的部分，从而将其中共同的点抽取出来形成的。
    (b) 抽象类拥有构造方法。
    (c) 对于成员变量，抽象类可以有多种修饰符。
    (d) 在方法实现上，抽象类可以包含具体的方法。

  2. 接口 (Interface)
    (a) 它的设计理念是在一开始就规定了某个类需要具备哪些方法、实现哪些功能。
    (b) Java 中的类只支持单继承，但可以实现多个接口。
    (c) 接口没有构造方法。
    (d) 接口的成员变量默认都是 public static final，所以经常用来定义常量。
    (e) 在方法实现上，Java 8 之前全部都是抽象方法；在 Java 8 之后，接口可以包含默认方法（Default Method）或静态方法（Static Method）。

4 java8新特性

Java 8 的新特性主要包括以下内容：

  1. 函数式接口（Functional Interface）
    (a) 只有一个抽象方法的接口，可以直接通过 Lambda 表达式实现。
    (b) 将函数式接口与 Lambda 表达式结合，可以实现匿名内部类的简写。

  2. Stream 流接口
    (a) 用于处理集合数据。
    (b) 支持链式调用，提供过滤（filter）、映射（map）、排序（sorted）等操作。
    (c) 支持并行流（Parallel Stream）。

  3. Optional 类
    (a) 封装可能为空的值，以减少 NPE（空指针异常）。
    (b) 提供了 orElse 或 ifPresent 等方法来处理空值。

  4. 新的时间日期 API
    (a) 新增了 LocalDate、LocalDateTime 等类。
    (b) 替代了原来线程不安全的 Date 和 Calendar 类。

6 java并发

6.1 基础概念与线程管理

6.1.1 进程与线程的区别是什么？

进程与线程的区别主要体现在以下几个方面：

  1. 基本单位
    (a) 进程是资源分配的基本单位。
    (b) 线程是 CPU 调度的基本单位。

  2. 内存空间与资源共享
    (a) 内存空间：进程之间相互独立，拥有独立的内存地址空间；而线程共享所属进程的内存空间。
    (b) 资源共享：线程可以共享进程的堆、方法区等资源。
    (c) 私有资源：每个线程拥有自己独立的程序计数器、虚拟机栈和本地方法栈。

  3. 创建与开销成本
    进程的创建与销毁涉及资源的分配与回收，切换成本和开销都很高；相比之下，线程的创建和切换成本更低，也更轻量。

  4. 通信方式
    在通信方式上，进程与线程存在显著差异：

  5. 进程通信
    进程之间需要更高程度的隔离，必须经过特定的 IPC（进程间通信）机制。通信方式相对复杂，常见的包括：
    (a) 管道
    (b) 消息队列
    (c) 共享内存等

  6. 线程通信
    由于线程共享所属进程的资源，通信实现相对简单。线程只需读取全局变量（即通过共享资源）即可实现数据交换。

6.1.2 创建线程有哪几种方式？推荐哪种？

创建线程归根结底都是调用 Thread 类的 run 方法。在形式上，主要有以下几种方式：

  1. 继承 Thread 类
    通过继承 Thread 类并重写其 run 方法来实现。

  2. 实现 Runnable 接口
    实现 Runnable 接口并重写 run 方法。

  3. 实现 Callable 接口
    实现 Callable 接口并结合 FutureTask 来创建线程。

  4. 使用线程池
    直接创建一个线程池，由线程池自动帮你创建并管理线程。线程池会自动处理线程的创建、分配与销毁。

实际上，无论是哪种创建线程的方式，到最终都需要去调用 Thread.start 方法。也就是说，虽然形式有很多，但实际上 Thread.start 才是唯一的入口。

比如说，对于继承 Thread 类的方式，它的本质在于：

  1. 其内部已经实现了 Runnable 接口
  2. 最终的执行依然是依靠其内部实现的 run 方法

6.1.3 run() 和 start() 有什么区别？

  1. run() 是一个普通的方法：
    调用 run() 只是在当前线程中执行普通的方法逻辑，并不会开启新的线程。

  2. start() 才是真正启用线程的方法：
    调用 start() 会通知 JVM 创建一个新的线程路径（线程实例），并由这个新线程去异步执行 run() 方法中的逻辑。

  3. 调用限制：
    每个线程对象的 start() 方法只能被调用一次。如果重复调用，系统会抛出异常。

6.1.4 线程的生命周期（状态）有哪些？状态之间如何转换？

线程的状态共有 6 种：

  1. 新建状态 (NEW)
    线程对象已经创建，但是还没有调用 start() 方法。

  2. 可运行状态 (RUNNABLE)
    调用了 start() 方法之后进入这个状态。这里的 RUNNABLE 实际上包含了操作系统层面的两种状态：就绪 (Ready) 和运行中 (Running)。也就是说，线程在 start() 之后不一定会马上运行，它只是可以被 CPU 调度了，具体执行时机取决于系统的调度。

  3. 阻塞状态 (BLOCKED)
    通常表示线程正在等待获取监视器锁（lock）。

  4. 无限期等待 (WAITING)
    线程需要等待其他线程进行显式唤醒。

  5. 限时等待 (TIMED_WAITING)
    线程会等待一段时间，到期后会自动恢复，不需要手动唤醒。

  6. 终止状态 (TERMINATED)
    线程执行完毕或者因异常结束。

状态转换过程：

  1. 新建到就绪 (NEW → RUNNABLE)
    线程从新建状态进入启动阶段。

  2. 阻塞状态 (BLOCKED)
    运行中的线程如果抢不到锁，会从 RUNNABLE 进入阻塞状态。

  3. 等待状态 (WAITING)
    需要别人进行唤醒时，线程会从 RUNNABLE 转换到 WAITING 状态。

  4. 限时等待 (TIMED_WAITING)
    如果是休眠或者限时等待的情况，线程会从 RUNNABLE 转换到 TIMED_WAITING。

执行结束的话，则会从 RUNNABLE 状态转为终止。

6.1.5 .sleep() 和 wait() 的区别？

Sleep 和 Wait 的区别主要体现在以下几个方面：

  1. 方法归属不同
    (a) Sleep 是 Thread 类的一个静态方法。
    (b) Wait 是 Object 类的一个方法。

  2. 锁的释放机制（最核心区别）
    (a) Sleep 不会释放当前线程持有的锁。即便线程进入了休眠状态，它依然占据着锁资源。
    (b) Wait 会释放当前线程持有的锁，让出资源以允许其他线程进入同步代码块。

  3. 用途与偏重点
    (a) Sleep 更偏向于线程调度，用于让当前线程暂停执行，休眠指定的时间。
    (b) Wait 更偏向于线程间的通信，它通常需要配合其他线程的唤醒操作（如 notify 或 notifyAll）来使用。

  4. 使用位置
    (a) Sleep 可以在任何地方使用。
    (b) Wait 只能在同步代码块（synchronized block）或者同步方法中调用，否则会抛出异常。

6.1.6 yield() 的作用是什么？

yield() 的作用是一个提示调度器，就是告诉 CPU 它可以暂时让出当前线程，让同优先级的其他线程先去执行。

但是，它只是提醒而非强制，调度器也可以完全不理会这个请求。
